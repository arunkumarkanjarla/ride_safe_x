Rules

Event rules

  • Events are facts in past tense (ride.completed), never commands.
  • Adding fields is allowed; removing or renaming a field needs a new version and both versions published during migration.
  • Consumers must be idempotent: the same event may arrive twice.
  • Order is guaranteed only per key, so everything about one ride uses ride_id as the key.
