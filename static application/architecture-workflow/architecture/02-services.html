Communication

How services talk

  • One owner per table. A service never reads another service's schema; it calls the API or keeps a local copy from events.
  • Sync only on the critical path. Quotes, ETA and dispatch are sync calls with a 300–800 ms timeout and a circuit breaker.
  • Idempotency keys on every POST that creates money or rides, so app retries never double-book or double-charge.
  • Transactional outbox. A service writes its row and its event in one database transaction; a relay pushes the event to Kafka.
  • Versioned APIs under /v1; mobile apps can lag several versions, so old versions stay supported for 12 months.
  • Start as a modular monolith. Each service is a separate Python package with its own schema, deployed together in phase 1 and split out when load requires it.
