Offline mode & sync

Shows what the driver app is doing when the network drops, so drivers trust that the trip and fare are safe.

When the network returns, everything uploads in order and the server reconciles the trip.

How it works

  1. Every action and GPS point is written to an encrypted local queue first.
  2. A background worker sends the queue in order when a network is available.
  3. The server accepts late data using event timestamps and recomputes the fare.
  4. Conflicts (for example the rider cancelled meanwhile) are resolved by server rules and shown to the driver.

What is on the screen

  • Offline banner
  • Queued items with counts
  • Last sync time
  • Retry

Edge cases and validation

  • Queue survives app restart and phone reboot.
  • Fare disputes caused by long offline gaps are reviewed by support.
