How it works

  1. Reads the stored refresh token from secure storage (Keychain / Keystore).
  2. Calls the config endpoint for minimum app version, city list and feature flags.
  3. If the app is too old, shows a forced-update dialog.
  4. Routes to onboarding (first launch), login (no session) or home (valid session).

What is on the screen

  • Logo and brand name
  • Tagline
  • Silent progress text

Backend calls

MethodEndpoint / channelWhy
GET/v1/config?platform=android&version=1.0.0Minimum version, feature flags, supported cities
POST/v1/auth/refreshRenew the access token if a session exists

Events published

None

Data used

  • Secure storage: refresh token, device ID
  • Remote config

Edge cases and validation

  • No internet: show retry banner, keep cached city config.
  • Refresh token rejected: clear session, go to login.
  • Rooted or tampered device: allow booking but flag device to Fraud.
