How it works

  1. Seat layout and availability come from the bus operator's system through the bus adapter.
  2. Seats are held for 8 minutes while the user pays.
  3. The ticket is issued by the operator; the app stores a QR code that works offline.
  4. Buses with GPS trackers share live location in the app.

What is on the screen

  • Bus summary
  • Seat map with women-reserved seats
  • Boarding points
  • Dropping point
  • Total
  • Offline ticket note

Backend calls

MethodEndpoint / channelWhy
GET/v1/bus/trips/{id}/seatsLayout and availability
POST/v1/bus/trips/{id}/holdHold seats 8 min
POST/v1/bus/bookingsConfirm after payment

Events published

bus.booked

Data used

  • Operator inventory (via adapter)

Edge cases and validation

  • Operator system slow: seats shown as 'checking' rather than wrong availability.
  • Operator cancels the trip: full refund and alternatives on the same day.
