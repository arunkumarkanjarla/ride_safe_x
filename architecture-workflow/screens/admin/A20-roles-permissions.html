Changes to roles need SUPER_ADMIN and are reviewed every quarter. Fleet managers get row-level limits to their own fleet.

How it works

  1. Permissions are fine-grained strings checked by every service.
  2. Roles bundle permissions; staff can hold several roles per city.
  3. Quarterly access reviews ask managers to confirm each person still needs their roles.

What is on the screen

  • Tabs for roles, users, access reviews
  • Permission matrix
  • New role

Backend calls

MethodEndpoint / channelWhy
GET/v1/admin/rolesRoles
PUT/v1/admin/roles/{id}Update permissions
POST/v1/admin/users/{id}/rolesGrant role

Events published

admin.role_changed

Data used

  • identity.roles, identity.role_permissions

Edge cases and validation

  • A user can't grant themselves a role.
  • Sensitive permissions (PII, government reports) need justification when granted.
